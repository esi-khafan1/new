DRY - Don't Repeat Yourself

Part 1: Foundationsprinciple

Definition

DRY means every piece of knowledge should have one authoritative representation. Knowledge is a business rule, invariant, protocol fact, or decision that must stay consistent, not merely text that looks similar.

Two code fragments may be syntactically alike but represent different policies. Copying those is sometimes correct. DRY is about avoiding multiple sources of truth that can silently disagree.

Problem It Solves

Duplicated validation, pricing, serialization, or authorization rules drift when one copy changes and another does not. Bugs then appear as inconsistent behavior between endpoints, jobs, and clients.

C++ Before

if (amount > 1000000) reject(); // API
if (amount > 1000000) reject(); // worker
if (amount > 1000000) reject(); // import job

C++ After

class TransferPolicy {
public:
  bool allowed(int cents) const { return cents <= 1000000; }
};

TransferPolicy policy;
if (!policy.allowed(amount)) reject();

The named policy becomes the place where the rule is reviewed, tested, and changed.

Trade-offs and Misuse

  • Premature extraction can couple unrelated policies and make names vague.
  • Prefer duplication temporarily when the requirements may diverge.
  • DRY applies to knowledge, not to every repeated token or loop.

Relationships

DRY complements SRP and single source of truth, but must be balanced with KISS and clear boundaries.
